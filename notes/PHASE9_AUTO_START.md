## Actual existing recording audit (2026-10-06)
Read-only `in-game-replay-tests --start-anchor replay_2026-10-06_075252.erplay` reports available=0. This specific older recording cannot use automatic return with the present scene verification. Native transform flags are reserved and emitted as zero; they are not interpreted as presence bits. The Reader validates transform contents; presence records retain their own semantics.

The CLI prints all actual candidates and endpoint poses for further investigation. Several distinct entities change their coordinates by approximately (-8,+8,-96) between endpoints. This is evidence consistent with Havok coordinate rebasing, not proof that each actor physically moved by that vector. Therefore endpoint coordinates and old block_id_origin must not be treated as permanent world coordinates. This feature is a bounded experimental return for eligible captures, not a complete automatic map restoration solution.

The pinned SDK position.rs documents block-local/global/Havok coordinate spaces; PlayerIns exposes block_position/current_block_id and safe_block_pos/safe_block_id. The next recording change should capture explicit player block-local pose, current block and a measured Havok-to-block reference at recording start and changes. That metadata requires live validation and cannot be retroactively invented for this existing file. No user requirement to remember or manually find its first XYZ is introduced; unsupported preparation reports the missing scene metadata instead.
