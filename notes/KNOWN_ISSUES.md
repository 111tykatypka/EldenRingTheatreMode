# Tester build known issues

- **Experimental existing-actor transforms, not complete gameplay reconstruction.** No new NPC runtime feature is verified. Retained player transform replay was verified historically by the user; this matching build still needs regression testing.
- AI ownership/input neutrality are not proven. Scoped flags + producer-stage normalized requests may be insufficient. Requested position vs actual physics corrections are logged; visual model/Havok synchronization and grounding remain unresolved.
- Recorded raw animation/action/time/rate fields do not prove executed attack/dodge semantics. NPC animations/actions are captured only. Player raw animation requests retain the previous opt-in experiment, OFF by default, with no exact phase/pose guarantees.
- No spawn/despawn/death reconstruction, resurrection, native AI snapshots, boss phase restoration, damage replay, projectile/VFX reproduction or world/save rollback. Recorded HP/item SFX values are observations, not replay events that trigger writes.
- Equipment/face/model snapshots are capture and inspection only. NPC gear/appearance beyond model ID is unavailable. No appearance/equipment restoration, quantities or inventory writes. Unknown fields stay unknown.
- Matching requires the same loaded native handle + entity/NPC/type. Reloading/death/map transition can invalidate the match. Actor disappearance expires its lease. The program never dereferences a cached object pointer to restore an actor; only the current reacquired matching object may have owned bits restored.
- Actor acquisition refuses a starting displacement over 20 units; later target steps over 5 units and stale target leases are rejected. This may exclude legitimate warps/fast boss motion. Rejections are explicit; no teleport loop or guessed map placement fallback.
- Radius hysteresis is spatial (enter R, exit 1.2R); lifetime cache is two seconds. Missing observations are not semantic spawn/death. Queue truncation can hide presence changes until the next complete frame.
- Capture and ownership have a configurable 1..16384 resource budget (default 1024); host queue 16 frames, 250 ms target lease. Long duration is uncapped, but disk, index memory, actor count, allocations/CPU and IPC throughput remain practical limits. Large actor batches stop when stale. No measured game overhead or guaranteed 60 Hz is claimed.
- Streaming recording avoids storing the entire recording in RAM. Playback indexes still grow with samples/lifetimes. Actor interpolation currently seeks records from disk; a dense 200-unit scene may need further caching after actual profiling.
- Paused playback holds transforms; native animations/world time can continue. Arbitrary in-game seek/step stops application first. Offline scrubbing and bookmarks remain available.
- Save isolation is not implemented. The replay deliberately writes no HP/inventory/progression fields, but the live world continues running and can still produce normal game side effects. Use the first nonlethal same-scene test and report unexpected side effects.
- Capture settings require a fresh DLL load; current settings controls are presets and may not reflect an older saved INI until explicitly saved. Default experimental flags are OFF. Loader/server lifecycle can require restarting the game after the host is closed.
- New host and DLL must be paired: character pipe version 2 carries 440-byte optional visual snapshots; an old host will not understand it. ERPLAY02 and earlier ERPLAY03 data remain readable; older hosts may reject mod version 0.6.0 even though optional tracks are structurally skippable.
- ImGui draw construction passed at five resolutions; this is not manual visual/DPI or Elden Ring acceptance testing. No new in-game overlay was added.
